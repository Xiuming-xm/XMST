### 1.3 目标信息架构（本表的落点）

- **一级导航 6 项**：`仪表盘` · `服务器` · `下载` · `内网穿透` · `工具` · `设置`
  - `仪表盘` **保留原位**（用户已拍板，2026-10-05）：同类工具均有此入口，且后续要承载「公告」与「成就」（蓝图见 §8）；不再降级为「工具 → 概览」。
  - `内网穿透` **保留原位**（用户已拍板，2026-10-05）：现设计已认可，不并入「工具」。
  - `工具` 收纳 `插件` / `日志` / `MC 百科` / `诊断` 等；`服务器` / `下载` / `设置` 维持原一级位置。
- **服务器详情 5–6 页签**：`概览` · `控制台`（= 现"服务器输出日志" + 现"服务器状态"的性能部分）· `文件 / 模组` · `备份` · `设置`（启动命令 / JVM / 端口 / 自动重启 / 定时 / 崩溃策略）·（保留）`玩家`（"玩家是否独立成页签"仍待拍板，见 §7）
- **统一规范**：每页顶部一条工具条（搜索/过滤 + 主操作）；设置一律「分组卡片 + 折叠」；「高级/实验」默认关闭；一页最多 5 个分组；每个选项一行弱化说明；危险操作二次确认；全局统一字体/间距/圆角。
- **日志页定位**：`日志` = 工具自身运行日志；服务器控制台日志在 `服务器 → 控制台`；穿透日志在隧道页。

## 3. 重复与高度重叠的区块（合并结论）

### 3.1 「服务器状态」与「服务器输出日志」→ 合并为「控制台」
- `ui_overview` 内的「服务器输出日志」+ 命令输入（L15284–15380）与 `ui_status` 的性能段（L14311–14324）渲染的是**同一运行时的两类视图**，现状被拆到两个页签。
- **结论**：新建 `控制台` 页签 = 性能条（`show_perf_bar`）+ 彩色日志（`show_colored_log`）+ 命令输入（含 ↑/↓ 历史）+ 崩溃报告分析（默认折叠）+ 启动前检查入口（默认折叠）。`ui_status` 与 `ui_perf` 两个函数随之移除，`ServerTab::Perf` / `ServerTab::Status` 合并为一个变体。

### 3.2 三处 JVM / Java 设置 → 单一归属 + 服务器侧覆盖
- `ui_scripts`「JVM 参数（{jvm} 占位符）」+ `使用推荐值`（L15562 附近）
- `ui_scripts`「user_jvm_args.txt」编辑器 + `保存`（L15591 附近）
- `ui_settings → Java 和 JVM → 默认 JVM 参数` + `使用推荐值`（L21011 附近）
- 三处都调用同一个 `recommended_jvm_args(phys_gb)`（L255 附近），逻辑同源但入口三份。
- **结论**：**保留 `设置 → Java` 的全局默认值**（`default_jvm_args`）为唯一权威；服务器「设置」页只保留「继承全局 / 覆盖」+ `user_jvm_args.txt` 编辑，并显示「当前生效值来自：全局默认 / 本服务器覆盖」。删除服务器页里重复的"推荐值"按钮文案，只在全局处保留一个。

### 3.3 「自动功能」与「服务器设置」→ 按主题拆成两个页签
- `ui_backup` 内「自动重启」（L18034）+「崩溃重启」（L18096）与 `ui_scripts` 的「启动脚本 / 启动方式」（L15500 附近）属同一决策链（谁拉起进程、失败怎么办、定时重启）。
- **结论**：`备份` 页签只留「备份基础 / 触发时机 / 排除与保留 / 存储总览 / 备份列表」；`自动重启`、`崩溃重启`、`启动脚本`、`Java / JVM`、`开机自启`、`server.properties`、`run.bat` 一起进「设置」页签，按「启动与 Java」「自动与崩溃策略」「服务器属性」三张卡片组织。

### 3.4 「日志」的三处入口 → 一处
- `ui_logs_page` 底部 `最大显示行数`（L24375）与 `设置 → 日志` 分区（L20871，只剩跳转说明）指向同一配置 `cfg.max_log_lines`。
- **结论**：删除 `设置 → 日志` 二级分区与卡片；`最大显示行数` 收进日志页工具条的「显示设置」折叠。同时把日志页说明改为"工具自身运行日志"，服务器输出汇总不再进该页（与 §1.3 定位一致）。

### 3.5 白名单 / 封禁 / 封禁 IP 两处 → 保留玩家管理
- `ui_whitelist_blacklist`（L15918，挂在服务器设置页）与 `ui_players_wl` / `ui_players_banned`（L16527 / L16584）表头列名、添加表单、按钮文案逐一对应。
- **结论**：**删除服务器设置页顶部的白名单/黑名单区块**（含 `ui_whitelist_blacklist` 函数），玩家管理为唯一入口。

### 3.6 「仪表盘」与「服务器列表」→ 保留并增强（不合并）
- 仪表盘的「在线服务器运行状况」表（L13700 附近）与服务器列表看似同一批数据，但分工不同：仪表盘是**运行总览**（跨服务器一眼看全），服务器列表是**逐台管理**。
- **结论**：`仪表盘` **保留一级并增强**（用户已拍板，2026-10-05；不再考虑"降级进工具"或"并入服务器列表"）。统计四个数字（启动次数/下载次数/首次下载/在线数）原地保留，并作为 §8 成就/里程碑系统的本地计数来源；增强方向见 §8（公告位、成就卡片）。

### 3.7 「背景效果」两处 → 设置 → 界面
- 插件页 `CollapsingHeader("配置")` 内的「背景效果 / 不透明度 / 内容衬底」（L21973 附近）与 `ui_theme_settings → 背景图 / 透明度`（L20551 附近）控制同一批材质参数。
- **结论**：材质参数统一到 `设置 → 界面 → 背景图` 折叠组；插件页只保留插件自身 KV 配置。

### 3.8 崩溃分析两处入口 → 控制台（默认折叠）
- `ui_status` 的「崩溃报告分析」列表与弹窗 `⚠ 崩溃原因分析` 是同一能力的两种呈现（列表 + 结果）。
- **结论**：保留控制台内的分析入口（默认折叠），弹窗只作为分析完成后的结果展示；`ui_status` 内的重复列表删除。
