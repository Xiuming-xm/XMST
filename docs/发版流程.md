# XMST 发版流程

> 一条命令完成发版；「容易忘的校验」由脚本固化，不靠人记。
> 脚本：`tools/release.ps1` ｜ 校验依据：`AGENTS.md` §3、§4.1、§7

---

## 1. 一条命令

```powershell
# ① 最常用：构建 + 备份 + 交付 + 校验 + 提交（不推送，最安全）
powershell -NoProfile -ExecutionPolicy Bypass -File F:\XMST\tools\release.ps1

# ② 指定版本并推送 master 与标签（打不开 GitHub 网页时的标准做法）
powershell -NoProfile -ExecutionPolicy Bypass -File F:\XMST\tools\release.ps1 -Version 0.1.2-alpha -Push -Tag

# ③ 复用已构建的 exe，只重新打包交付（跳过 cargo，秒级完成）
powershell -NoProfile -ExecutionPolicy Bypass -File F:\XMST\tools\release.ps1 -SkipBuild
```

- 可在**任意目录**调用（脚本用 `$PSScriptRoot` 的上一级推导项目根）。
- 装了 PowerShell 7 的话，把 `powershell` 换成 `pwsh` 同样可用；本机目前只有 Windows PowerShell 5.1。
- `-ExecutionPolicy Bypass` 只作用于本次调用，脚本本身**不会**改执行策略。
- 不带 `-Version` 时读 `Cargo.toml` 的 `[package] version`。

## 2. 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Version <字符串>` | 取 `Cargo.toml` 的 version | 与 `Cargo.toml` 不一致时**以参数为准**并自动改写 `Cargo.toml` |
| `-SkipBuild` | 关 | 跳过 `cargo check` + `cargo build --release`，直接用 `target\release\xmst.exe`；会提示产物是否比源码旧 |
| `-Push` | **关** | 只有显式加才 `git push origin master` |
| `-Tag` | 关 | 创建标签 `v<版本>`；配合 `-Push` 一起推送 |

## 3. 脚本做的 10 步

1. 检查工作区状态（有未提交改动 → **警告并列出**，之后会一并提交）
2. 确定版本号；与 `-Version` 不一致时更新 `Cargo.toml`
3. `TMP`/`TEMP` → `temp\ctmp` → `cargo check` → `cargo build --release`（`-SkipBuild` 则跳过）
4. 结束所有 `XMST*` 进程（容错；若仍有存活则中止）
5. 旧 `dist\XMST-*.exe` 备份到 `dist\backup\<yyyyMMdd_HHmmss>\`，只保留最近 2 份备份目录
6. 复制产物到 `dist\XMST-<版本>.exe` 与 `versions\<版本>\XMST-<版本>.exe`，写 `versions\<版本>\SHA256.txt`
7. 交付前校验（见下节）
8. `git add -A` + `git commit`（信息 `release: <版本> 交付产物与版本号同步`）；`-Tag` 时建标签
9. 仅 `-Push` 时推送 master（+ 标签），并打印 `git ls-remote origin` 关键行确认
10. 打印发版摘要 + 手动待办

产物位置：

| 路径 | 用途 |
|---|---|
| `dist\XMST-<版本>.exe` | 本机交付/自测用的产物（`dist/` 不入库） |
| `versions\<版本>\XMST-<版本>.exe` + `SHA256.txt` | **对外下载**的那一份（`versions/` 会提交入库） |
| `dist\backup\<时间戳>\` | 旧版回退副本（保留 2 份） |

## 4. 固化了哪些校验（AGENTS §7）

- `dist` / `versions` / `target\release\xmst.exe` **三处 SHA256 一致**，且 `SHA256.txt` 内容与产物哈希一致
- 产物有 **PE 头（MZ）**，避免复制出空壳/文本文件
- **完整性标签必须 Medium**：文件无独立标签时逐级向上查目录；查出 **Low 直接中止**并打印修复命令
- **MOTW（Zone.Identifier）**：检测到就 `Unblock-File` 并提示
- 所有外部命令（cargo / git / icacls）**退出码都检查**，失败即明确报错并停止
- 旧产物先备份、备份目录保留 2 份

## 5. 常见问题

### 5.1 打不开 GitHub 网页，只想用命令行推送

脚本已内置 SSH 参数，加 `-Push` 即可（需要时再加 `-Tag` 连标签一起推）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File F:\XMST\tools\release.ps1 -Push -Tag
```

推送前脚本会先用 `git ls-remote origin` 探测连通性，失败会给出明确提示而不是卡死；推完会打印远端 `refs/heads/master`（和标签）行作为确认。

只想推送（不想重跑整个发版流程）：

```powershell
$env:GIT_SSH_COMMAND='ssh -o BatchMode=yes -o ConnectTimeout=15'
git -C F:\XMST push origin master
git -C F:\XMST push origin refs/tags/v0.1.2-alpha     # 只推某个标签
ssh -T git@github.com                                 # 单独验证 SSH 是否通
```

**GitHub Release 附件可以稍后再补**（网页打不开就不做）：标签已经推上去，等网络方便时再在 `https://github.com/Xiuming-xm/XMST/releases/new?tag=v<版本>` 上传 `versions\<版本>\XMST-<版本>.exe` 即可；脚本摘要里会把该链接和附件路径打印出来。

### 5.2 完整性标签是 Low 怎么办

判定与修复：

```powershell
icacls "F:\XMST\dist" | Select-String 'Mandatory Label'   # 期望 Medium，若是 Low 就是它
icacls "F:\XMST" /setintegritylevel M /T /C               # 修复（脚本中止时会直接打印这条）
```

- 改完**必须重启程序**（运行中的进程保持旧令牌）。
- Low 会让程序被降级运行，文件写入 / 改名 / 复制与"打开目录"等 shell 交互**全部失效**（详见 `AGENTS.md` §4.1）。
- 脚本在步骤 7 查出 Low 会**中止**，不会提交也不会推送。

### 5.3 MOTW / "无法验证发布者"

- 从浏览器、聊天软件下载的 exe 会带 `Zone.Identifier`（MOTW）；脚本对交付产物自动 `Unblock-File` 并提示。
- 手动查看/解除：`Get-Item -LiteralPath <文件> -Stream Zone.Identifier` / `Unblock-File -LiteralPath <文件>`。
- 对外分发建议打成**普通 zip**，并提示用户用 **7-Zip 解压**（资源管理器解压可能重新打上 MOTW）。
- 未签名的 exe 必然弹"未知发布者"，属正常现象；要彻底消除需要代码签名证书。

### 5.4 用 Gitee 做国内镜像

脚本只推 `origin`（GitHub）。国内镜像需要自己加远端并推送：

```powershell
# SSH 方式
git -C F:\XMST remote add gitee git@gitee.com:<你的Gitee用户名>/XMST.git
# 或者 HTTPS 方式（SSH 不通时；首次会提示输入账号/令牌）
git -C F:\XMST remote add gitee https://gitee.com/<你的Gitee用户名>/XMST.git

git -C F:\XMST push gitee master
git -C F:\XMST push gitee refs/tags/v0.1.2-alpha
git -C F:\XMST remote -v          # 查看已配置的远端
```

推送慢/失败的临时办法：`git config --global http.postBuffer 524288000`（HTTPS 大文件），或改用 SSH。

### 5.5 其它

| 现象 | 处理 |
|---|---|
| `仍有 N 个 XMST 进程在运行` | 手动退出程序（含托盘）后重跑；脚本第 4 步已尽力结束 `XMST*` |
| `无法访问远端 origin（SSH）` | 先 `ssh -T git@github.com`；确认 SSH key 已加入 GitHub；或改用 Gitee 镜像 |
| `暂存区没有改动` | 正常：本次没有文件变化（例如内容完全相同的重复发版），沿用当前 HEAD |
| `复制文件失败` | 文件被杀软/其它进程占用；脚本已重试 3 次，关掉占用方再跑 |
| 想回退到上一版 | 用 `dist\backup\<时间戳>\` 里的旧 exe；代码按提交回退（`git log` / `git revert`） |

## 6. 发版后手动待办（脚本不做）

- [ ] GitHub 建 Release 并上传 `versions\<版本>\XMST-<版本>.exe`（网页打不开可延后）
- [ ] 仓库 `Settings → Branches` 把默认分支设为 **master**
- [ ] 需要的话把 tag/分支镜像到 Gitee（§5.4）
