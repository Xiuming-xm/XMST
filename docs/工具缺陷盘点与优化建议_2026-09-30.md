# XMST 缺陷盘点与优化建议（2026-09-30）

本文档回答三个问题：**① 还缺什么功能；② 有哪些逻辑缺陷；③ UI 如何优化。**
所有结论基于本轮对 `src/{main,plugins,theme,config,features,backdrop}.rs` 的逐段阅读与真机实测
（实测方法与数据见 `docs/背景材质失效根因分析_毛玻璃亚克力半透明.md` §9/§10）。
标注「已修」的是本轮已落地的改动；其余为待办。

## 1. 逻辑缺陷（按严重度排序）
> **2026-09-30 更新**：**D1 / D2 / D5 / D6 / D7 / D9 / D11 已在本轮修复并构建部署**
> （cargo check 0 error、release 构建通过、`dist\XMST-0.1.0-alpha.exe` SHA256
> `1409013853FDA1BF3635EDFC07763FC4CD3F77E8D12C2821A8C5B2F3576C7AE0`）。
> 仍待处理：D3（插件权限模型）、D4（背景状态单一真源）、D8（i18n/`lang` 字段）、
> D10（捕获调度细化：拖动中冻结底图）。

### D1【中】`main_hwnd()` 每帧枚举全部顶层窗口（性能 + 脆弱）
`fn main_hwnd()` 用 `EnumWindows` + 标题包含 `"XMST"` 来找主窗口，而
`apply_window_round_region()` **每帧**都会调用它（`tick_theme` → 圆角区域）。
- 代价：每帧一次全系统顶层窗口枚举（几十~几百个窗口），纯浪费；
- 脆弱：标题一改、出现第二个含「XMST」的窗口（托盘消息窗、未来的多窗口）就会选错。
**建议**：窗口创建后取一次 HWND 缓存在 `App`（eframe 可用 `CreationContext`/`raw_window_handle`
或首次 `main_hwnd()` 成功后缓存），仅在 `IsWindow` 失败时重新解析。

### D2【中】背景效果与「生效来源」没有仲裁
`plugin_configs[*].bg_style` 是**每个插件各自一份**，但窗口背景全局只有一个：
- 多个插件同时请求时，后触发者覆盖先触发者，无优先级/无「谁在生效」提示；
- 禁用/卸载某个插件时，**不会**回收它设置的效果（只有关闭 BETA_PLUGINS 总开关才会复位）。
**建议**：`App` 记录 `bg_owner: Option<插件名>` + 请求时间戳；禁用/卸载 owner 时自动复位；
多插件冲突时按「最后请求优先 + UI 明示」处理。

### D3【中】插件 manifest 没有权限模型
脚本 API 目前能：写配置、弹通知、改窗口背景、读资源目录。manifest 只有
`events/max_operations/resources`，**没有 permissions**。
一旦后续开放文件/网络/进程能力（插件系统天然会走到这一步），任何 zip 都能为所欲为。
**建议**：manifest 增加 `permissions: ["config","notify","window.bg","fs:read:资源目录", ...]`，
宿主在注册 API 时按权限裁剪（无权限就不注册该函数，脚本报 `ErrorFunctionNotFound`，语义天然）。

### D4【中】插件效果状态双份存储，可能不一致
`plugin_bg_opacity`（内存）与 `plugin_configs[name].bg_alpha`（磁盘）是两份：
- 只有点模式按钮/拖滑杆时才写回配置；脚本 `xmst_config_set("bg_alpha", ...)` 改了配置后，
  若宿主没有重新读取，界面显示与实际生效会不一致；
- 目前靠 `apply_bg` 里写回 + `tick_plugins` 每次读取缓解，但**没有单一真源**。
**建议**：以 `plugin_configs` 为唯一真源，`plugin_bg_opacity` 仅作为「本帧渲染缓存」。

### D5【中】`server_started` 依赖日志字符串 `"Done ("`
`main.rs` 用 `buf.contains("Done (")` 判定服务端就绪并发 `ServerStarted`：
- 非英文 locale、代理端（Velocity/BungeeCord 子服）、Forge/NeoForge 老版本的启动完成行
  可能是 `Done (12.345s)! For help...` 之外的形态 → 事件漏发，插件效果不触发；
- 已有 180s「未检测到就绪标志」提示，但没有兜底触发。
**建议**：正则匹配 `Done \([\d.]+s\)!`，或在超时后按「已运行 N 秒」补发一次 `server_started`。

### D6【低】插件缓存目录直接用插件名拼路径
`cache_dir.join(&manifest.name)`，`..`/绝对路径已拦截，但没有字符白名单：
名字含 `\ / : * ? " < >` 或超长时 `create_dir_all` 会失败且只留在日志里。
**建议**：把插件名做 slug 化（`[A-Za-z0-9._-]`，其余转 `_`）后再拼目录。

### D7【低】`bg_debug.log` / `crash.log` 无轮转
用 `OpenOptions::append` 无限追加（崩一次写一整段 backtrace）。
**建议**：超过 512KB 时截断重写（或保留最近 N 行）。

### D8【低】`lang` 配置项形同虚设
`GlobalConfig.lang` 存在且默认 `"zh"`，但界面字符串全部硬编码中文，没有 i18n 框架。
要么实现，要么删掉该字段（避免「配置项无实现」的误导）。

### D9【低】插件 `emit` 是广播，`on_enabled` 语义粗糙
启用插件 A 会让**所有已启用插件**都收到 `enabled`。当前 demo 包无所谓，
但多插件下会产生意外的副作用（每个插件都重设一次背景）。
**建议**：`emit_to(name, event, args)` 单播 + `broadcast` 保留给真正的全局事件。

### D10【低】捕获背景的刷新策略过于固定
`backdrop.rs` 固定 80ms 抓一次；窗口拖动/最大化/切换模式时（几何变化）应**立即**重抓
（`update(..., force: true)` 已实现但未被调用）。
**建议**：在 `apply_bg`、窗口尺寸/位置变化、拖动结束事件里 `force=true`；
静止时把间隔放宽到 200–300ms 省电。

### D11【低】「窗口排除抓屏」是隐性行为，缺开关与告知
`WDA_EXCLUDEFROMCAPTURE` 会让 **XMST 在用户录屏/共享屏幕里消失**（这是抓屏底图不自我递归的前提）。
目前只在代码注释里说明，UI/文档未告知，也没有关闭入口。
**建议**：配置项 `bg_capture_exclusion`（默认开）+ 插件卡片里一行说明；
关闭时退化为「不抓桌面」的纯半透明（在可合成的机器上仍由 DWM 路径工作）。

## 3. UI 优化建议

### 3.1 插件页（背景效果入口）
1. **入口位置**：背景效果藏在卡片内 `CollapsingHeader("配置")` 且默认折叠。用户本轮就是「找不到/以为没生效」。
   建议：卡片内**常显一行效果摘要**（`背景：毛玻璃 55%`）+ 右侧「设置」按钮，点开才是完整控件；
   或给生效中的卡片加一个色点徽章。
2. **控件密度**：现在是「4 个按钮 + 1 个滑杆 + 1 段长说明」挤在折叠区。
   建议：三模式做成 `SelectableLabel` 分段控件（radio 组）而不是 4 个独立按钮（「恢复默认」独立成小按钮），
   滑杆右侧加数值框，说明文字改为 `?` 悬浮提示（当前那段 60+ 字的长句在窄窗口会换行成 3 行）。
3. **缺少预览**：可以在滑杆旁放一个 24×24 的「效果预览块」（用当前背景色 + alpha 画一个圆角矩形，
   直观展示不透明度），比纯文字「不透明度 55%」更直观。
4. **一键对比**：加「按住对比默认背景」（按住时临时切 Default，松开恢复），一秒判断效果是否生效。
5. **诊断入口**：把 `bg_debug.log` 最后 5 行放进卡片「诊断」折叠区（并说明该文件路径），
   用户遇到问题可直接截图，不必找文件。

### 3.2 全局一致性
6. **状态双写**：顶部工具栏的「背景效果：xx」与卡片内「当前：xx」重复。建议只保留一处（顶部做全局状态，
   卡片只显示该插件保存的偏好，并标注「未生效/生效中」）。
7. **toast 过载**：`set_toast` 单槽位，后一条覆盖前一条；启用插件 + 应用背景会连发两条，
   用户只看到最后一条。建议改为队列（保留最近 3 条）或合并成一条。
8. **文案层级**：本工具大量使用「弱化小字」做说明，在自定义亮色主题下对比度偏低；
   建议统一走 `theme::light_adapt` 派生（已有函数，未被全部文案使用）。
9. **圆角与不透明的观感冲突**：窗口圆角由 `SetWindowRgn` 裁剪，捕获底图是矩形；
   若未来做「窗口阴影」要注意阴影会被 region 裁掉。

### 3.3 交互细节
10. **拖动窗口时背景滞后**：捕获式背景在拖动中会「拖影」。建议拖动开始时把底图**冻结**（停抓 + 保持上一帧），
    拖动结束再 `force` 抓一次（`BackdropCapture::update(force)` 已具备）。
11. **效果切换的反馈**：`apply_bg` 会立刻改窗口外观，但卡片 UI 要下一帧才更新「当前：xx」；
    建议点击后立即 `ctx.request_repaint()`（已加）并在按钮上给一次点击态。
12. **滑杆步进**：`0.05..=1.0` 线性滑杆不好精确调到 0.5；建议加 `step_by(0.05)` 或数值输入框。

## 4. 建议的下一步优先级

1. **D1**（缓存 HWND）—— 每帧枚举窗口是纯粹的浪费，改动小、收益确定。
2. **D2 + D11**（效果仲裁 + 排除抓屏开关）—— 直接决定功能的可预期性与合规观感。
3. **F1 + F2**（窗口记忆 + 效果自检提示）—— 用户体感提升最明显。
4. **3.1 的 1/2/5**（插件页入口 + 控件重构 + 诊断入口）—— 把「用户找不到/看不懂」根治。
5. **D3/F3**（插件权限）—— 在开放更多脚本能力**之前**做，否则后患。
6. **D5/D6/D7/D8/D9/D10** —— 低风险清理，可随手带上。
